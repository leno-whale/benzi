# 01-架构方案 · 《本子》v0.2 平衡性改造

> 架构员写给代码员。所有改动只在 `notebook.py` 单文件内，仅标准库，Python 3.14。
> 本版只做方向 1（原话不自动抄）+ 方向 3（收紧醒来预算），不做方向 2、不改叙事主线、不动七个结局的判定结构。
> 结论先行：**推荐「A 最小改动」——新增 `抄` 动词、`move()` 不再自动抄写、`WAKES` 14→12；预算定 12，文案「十四次醒来」改「十二次醒来」。**

## 1. 问题与目标

v0.1 的机制不咬人：一条固定十步路线 `nneeswseww` 扫遍九间屋，300 个种子 300 局全胜，不写一个字、不验一页，醒来预算和三页纸从来没成为约束。游戏像走迷宫，而不是「你的记忆只有三页」。

基线数字（领航员实测，直接引用）：

- 九宫格，门厅 `(0,0)`，三张原话藏在其余 8 间中的 3 间。收齐三张再回门厅的最短步数只有三种：**4 步（1 种布局）、6 步（18 种）、8 步（37 种）**，共 56 种布局。
- 原版十步扫荡 `nneeswseww` 恰好 10 步走遍 9 间并回门厅。
- 加入「每张原话抄写花 1 次醒来」后：扫荡成本 = 10 + 3 = **13**；最优通关成本 = 最短步数 + 3 = **7 / 9 / 11**。
- 固定预算余量（预算 − 最优成本）：WAKES=11 → 4/2/0（8 步布局零容错）；WAKES=12 → 5/3/1（13>12，扫荡刚好失败）；WAKES=13 → 扫荡仍赢。

改造目标（可测）：十步扫荡（不抄）胜率 = 0；十步扫荡 + 抄 = 0；全知最优 = 100%；「三页」和「醒来次数」成为真约束；七个结局与「四条硬事实」不破坏。

## 2. 三套顶层架构（+ 一套组合）

### A. 最小改动：新增 `抄` 动词，`move()` 不再自动抄写

**数据流 / 状态机（纸的一生）：**

```
纸在 hidden[房]（初始布局，未抄）
   │  走进该房 → 只是「看见」，不 pop，不 push
   ▼
看见（self.pos in self.hidden，由 show() 显示「桌上有一张纸」）
   │  离开 → 遗忘（hidden 不动，纸还在桌上，重进还能再看）
   │  `抄`（花 1 次醒来）→ hidden.pop(房) + pieces.append + push(piece=True)
   ▼
已抄（进本子，占一页，挤不掉；离开就真的带走了）
```

- **新增状态字段：无。** 「看见」是派生量：`self.hidden.get(self.pos)` 非空即「面前有未抄的纸」。`hidden` 语义从「该房有原话（进门自动收）」变为「该房有未抄的原话」；`pieces` 语义从「已收集」变为「已抄进本子」。
- **动作表：** `n/s/e/w`（走）、`写 <话>`、`抄`（新）、`验 <页码>`、`看`、`退`。只动 `move()`（删 7 行自动抄）和 `play()`（加 `抄` 分发 3 行），新增 `copy()` 方法（约 16 行）。
- **页面模型：** 完全复用现有 `push()`（三页上限、原话 `piece=True` 挤不掉、满则挤最旧非原话页）。不改。
- **预算模型：** `WAKES = 12`（改 1 个常量 + 文案）。
- **改动面：** `notebook.py` 约 35 行（删 7、增 copy 16、增 show 显示 7、增 play 分发与帮助 4、常量/文案 5）；`test_notebook.py` 重写扫荡组 + 新增抄写语义组，约 120 行。
- **优点：** 风险最低；七个结局、`push`、假页、验页全部原样；改动集中在「抄写」一个语义点，易回归。**缺点：** 预算仍是裸常量（无策略对象），未来若要动态预算需再改一处；页面槽位仍是隐式模型（靠 `piece` 标志）。

### B. 页面槽位 / 锁定页方案

把「三页容量」显式做成槽位对象，抄写必须落进一个空槽或挤掉最旧未锁定页。

- **数据流 / 状态机：** `Notebook.pages` 改为 `PageSlot[3]` 数组，每槽 `{text, ink, real, locked}`；`locked=True` 只对原话。`push()` 改为 `alloc(text, locked=False)`：找空槽 → 落槽；无空槽 → 找最旧 `locked=False` 槽挤出。
- **动作表：** 同 A（`抄`/`写`/`验`/`走`/`看`/`退`），但写入统一走 `alloc()`。
- **页面模型：** 显式槽位 + `locked` 标志；「原话挤不掉」由 `locked` 表达，「挤最旧非原话」由「最旧未锁定」表达。
- **预算模型：** 同 A（`WAKES=12`）。
- **改动面：** `notebook.py` 约 90–130 行（重构 `push` → `alloc` + 槽位类，`show`/`verify`/`ending_text` 跟着改遍历）。
- **优点：** 「三页」模型更清晰，为将来方向 2（假页挤未锁定笔记）留了自然落点。**缺点：** v0.2 用不上方向 2；现有 `push()` 已经靠 `piece` 标志正确实现「锁定/挤最旧」，重构是重写同一套语义，纯增风险。

### C. 动作表 + 预算策略对象方案

把「每个动作的成本」和「预算怎么算」抽成对象，主循环改为查表驱动。

- **数据流 / 状态机：** 同 A 的纸生命周期；但主循环 `play()` 不再内联 `if/elif`，而是查 `ACTIONS[verb]`（前置谓词、effect 回调、cost）。回合推进 = `cost` 累计 → 超预算判负。
- **动作表：** `ACTIONS = {"n": Action(cost=1, ...), "写": ..., "抄": Action(cost=1, pre=看见纸, effect=copy), ...}`，每项声明式。
- **页面模型：** 同 A（复用 `push`）。
- **预算模型：** `BudgetStrategy` 抽象，`FixedBudget(12)` / `DynamicBudget(+4)` 可插拔；测试注入不同策略即可验证「12 杀扫荡、13 扫荡赢」。
- **改动面：** `notebook.py` 约 100–160 行（新增 Action/Budget 类 + 主循环重写）。
- **优点：** 可测性最好，预算/动作成本可注入；将来动态预算一行切换。**缺点：** 对一个 526 行单文件游戏明显过重；本版已定「固定 12、不做动态」，策略对象的价值落空；主循环重写是最大回归源（`check_end`/`next_round`/`finish` 的调用顺序容易被改坏）。

### D. 组合（可选）：A 的结构 + 单一预算函数 + 独立纸生命周期

本质是 A，再把「预算」和「抄写语义」各收拢到一个命名点：

- **预算单点：** `def budget(): return 12`，`WAKES = budget()`；测试要验证「13 扫荡会赢」时 `monkeypatch` 掉它即可，不必改模块。
- **纸生命周期单点：** 已有 `copy()`；`show()` 只读 `hidden`，不改它。
- **改动面：** 比 A 多一个 `budget()` 函数（3 行）。

**结论：D 的预算函数在 v0.2 无必要**——`WAKES` 已是模块级常量，测试直接 `nb.WAKES = 13` 即可注入，`budget()` 只是多一层间接。故只作「可选微调」列出，不推荐单独实现。

## 4. 推荐方案

**推荐 A（最小改动），预算定 12。** 理由：

1. **改动面最小、风险最低**，而 v0.2 的唯一目标是「让机制咬人」，不是重构引擎。`push()` 已正确实现「原话锁定 + 挤最旧非原话」，B 的槽位重构是重写同一套语义。
2. **C 的策略对象价值落空**：本版明确不做动态预算（动态预算会打破「十二次醒来」且玩家无法预知自己的预算），固定 12 只需要一个常量。
3. **可测性已够**：`WAKES` 是模块级常量，测试可直接改它来验证「13 会让扫荡复活」，不需要 `BudgetStrategy`。
4. 抄写语义全部收进新 `copy()` 方法，`show()` 只读 `hidden`，单点易测、易回归。

不做 B/C 的原因：B 是过度设计（方向 2 本版不做）；C 是过度抽象（单一预算值不需要策略对象）。D 的 `budget()` 函数可有可无，不引入。

### 5.0 八个设计问题的逐条结论

| # | 问题 | 结论 |
|---|---|---|
| 1 | 抄写动词 | **新增 `抄`（无参数），别名 `copy`**。不并入 `写`，不用 `写 原话`（见 5.2） |

### 5.1 状态字段（新增/修改/删除）

- **新增：无。**
- **修改（语义）：**
  - `self.hidden`：仍为 `{房: 原话}`，但**只在 `抄` 时 pop**；进门不再 pop。含义 =「还没抄进本子的纸，仍在房里」。
  - `self.pieces`：仍为已得原话列表，但**只由 `抄` append**。含义 =「已抄进本子的原话」。
- **删除：** `move()` 里 332–340 行的自动抄写块（pop hidden / append pieces / push piece）。
- **日志新增：** `copy()` 成功时 `self.log.append(("copy", self.round))`。用于不变量测试与观测，不参与结局判定（`counts()` 不读它，A/B 仍只看 `("write", …)`）。

**`抄` 精确实现（写进 `Notebook`）：**

```python
def copy(self):
    if self.pos not in self.hidden:
        print(f"{C['dim']}这里没有纸可抄。{C['off']}")
        return False
    piece = self.hidden[self.pos]
    if not self.push(piece, piece=True):          # 防御：正常不会失败（只有三张原话）
        print(f"{C['dim']}本子满了。三页都被原话占着 —— 你在心里念了一遍，没地方抄。{C['off']}")
        return False
    self.hidden.pop(self.pos)
    self.pieces.append(piece)
    self.log.append(("copy", self.round))
    print(f"{C['ye']}你把这句话抄进本子：{C['off']}")
    print(f"  {C['ye']}「{piece}」{C['off']}")
    print(f"{C['dim']}（这一页挤不掉。它不是笔记，是原话。）{C['off']}")
    return True
```

**问题 1 的失败分支回答（先写自己的话 / 先看 / 抄过又回来）：**

- 先 `写` 自己的话、再进纸房：`写` 与 `抄` 是两个动词，互不干扰；`抄` 时若本子满，`push` 会挤掉最旧非原话页（常是刚写的自己话），符合设计。
- 站在纸前先 `看`：`看` 免费且会显示纸文本（`show(full=True)` 也走上面那段），看清了再决定抄不抄。
- 抄过又回来：`抄` 后 `hidden.pop`，再回来 `self.pos not in self.hidden`，`show()` 不再显示纸，`抄` 报「这里没有纸可抄。」；**没抄就离开再回来**，`hidden` 未动，纸还在，可再看再抄。

### 5.3 回合推进 / 假页 / 挤页 / 胜负的精确顺序

`play()` 主循环每轮顺序（保持不变，只加 `抄`）：

1. `show()`：显示房间、纸（若在纸房）、本子、原话计数 `已抄原话 X/3`、本子背面（`看` 时）。
2. 读命令 → 分发。
3. 若动作返回 `True`（真花费）：
   a. `check_end()`：`len(pieces) >= 3 且 pos == (0,0)` → `over = "win"`。
   b. 若未 `over`：`next_round()` → `round += 1`；`round > WAKES` 则 `over = "lose"`；否则 `round % 3 == 0 且 fake_pool` 时 `push(fake, ink=0, real=False)` 并 `log("fake", round)`。

- **假页：** 仍在第 3/6/9/12 次醒来出现，规则一字不改。`WAKES=12` 时判负局仍推到第 12 次醒来 → 4 张假页，硬事实 #4（`pieces<3` 判负局 `fake_written=4`）仍成立。
- **挤页：** `push()` 满则挤最旧非原话页；原话永不被挤。不改。
- **胜负顺序：** 赢在动作后 `check_end`（`抄` 在纸房发生，纸房非门厅，所以**必先抄齐再走回门厅**才赢）；输在 `next_round`（round 越界）。

### 5.4 预算

- `WAKES = 12`（原 14）。`抄` 花 1 次醒来（由「动作返回 True」隐式扣，与 `写`/`走`/`验` 同构，无需额外字段）。
- 数值依据：
  - 十步扫荡 + 3 抄 = 13 > 12 → 扫荡死。
  - 全知最优 7/9/11，余量 5/3/1 → 8 步最坏布局仍留 1 次容错（固定 11 则 8 步零容错，太狠）。
  - 固定 13 会让扫荡复活，否决；动态「最短步数+4」= 8/10/12 打破「十二次醒来」且玩家无法预知自己预算，否决。
- **「十四次醒来」处理：改「十二次醒来」。** 剧本中「十四」无特殊含义（只是「一天的长度」），换数不伤叙事；结局文本 `第 {wakes} 次醒来用完了` 走占位符，`WAKES=12` 自动变「第 12 次」，无需手改结局文本。硬编码「十四」只出现在 docstring 与常量注释，需手改（见 5.6）。
- **盲玩代价与预算决策（问题 6 + 领航员 POMDP 数据）：**
  - 盲搜上界（领航员用部分可观测动态规划实测）：**固定 12 = 62.5%；固定 11 = 62.5%；固定 13 = 100%**（13 时十步扫荡 10+3=13 仍赢，杀不掉旧解）。策略对比：12 时「扫荡」62.5%、「最近邻」仅 35.7%。**12 下最优策略就是扫荡，37.5% 的局在布局揭晓前就注定输，玩家没有能提高胜率的选择。**
  - 我的偶校验证明（9 格棋盘哈密顿路径末格必为偶校验格，距离门厅 ≥2 步，成本 ≥ 8+2+3=13）独立推出同样的 62.5% 天花板，与 POMDP 一致。11 与 12 天花板相同（被「末格」那 21 种布局钉死），但 11 把 8 步布局的全知余量压到 0，故 **12 严格优于 11**；13 直接复活扫荡，否决。
  - 信息补偿的代价（领航员 POMDP）：开局知道 1 张纸位置 → 71.4%；2 张 → 83.3%；3 张 → 100%（退化为纯路线题 7/9/11）。

## 8. 风险与已知局限

1. **盲玩是硬 mode、输局多来自布局（已拍板接受）：** 盲搜上界 62.5%（固定 11/12 相同，13 为 100%），且 12 下最优策略就是扫荡——37.5% 的局在布局揭晓前就注定输，玩家没有能提高胜率的选择。这意味着纯 1+3 的盲玩与「每一步都得算」确有张力：盲局更像布局抽签，真正的「每一步都得算」落在 `--seed` 重玩的记忆局（全知 100%，8 步布局余 1）。**已明确不做信息补偿**：`剧本.md` 第 25 行「三张纸的位置每天都变，所以你只能一间一间走」禁止开局标出纸的位置；任何在世者都不知道今天的布局，「开局知道」无叙事来源。此张力如实记录，不视为缺陷——它是「你每次醒来都不记得、但玩家记得」主题的正面表达。
2. **验页边缘化：** 最优通关（走最短路线 + 抄 3 次）从不用 `验`。假页会被抄写挤掉，`验` 只在**非最优的败局分支**里决定 C/D/G 的走向，或在你大量写自己话时腾页。如实记录，**不改假页规则**（遵循简报禁令）。
3. **「十四次醒来」文案：** 改为「十二次醒来」，叙事锚点数变了；结局文本靠占位符自动跟进，但 docstring 与根目录文档需手改。若作者坚持「十四」是核心意象，需另行拍板（见 §10）。
4. **方向 2 未做：** 假页仍不会主动挤「你还没锁的笔记」，只会在抄写/写满时被动被挤；「三页容量」对最优路径仍是软约束（不写自己话就不用为容量发愁）。已按简报明确留到后面。
